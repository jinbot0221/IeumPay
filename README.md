# 이음페이 MVP

기획서 v0.5 기반의 태블릿 대응 웹앱 개발 프로토타입입니다. Node.js 24 이상에서 외부 패키지 없이 실행합니다.

```sh
cd /workspace/IeumPay
npm start
# 별도 터미널
npm test
```

기본 주소는 로컬 포트 3000이며 기본적으로 127.0.0.1에 바인딩합니다. HOST, PORT로 변경 가능합니다. SQLite 데이터는 무시된 `.data/demo.sqlite`에 보관됩니다. 테스트는 메모리 DB로 운영 데이터를 변경하지 않습니다.

## 구현

- 가맹점 POS: 금액 입력, 코인 및 카드·삼성페이·애플페이·카카오페이·네이버페이 선택
- 테스트 지갑: 유료 100,000 / 혜택 5,000 코인, 1코인=1원 가정
- 원자적 코인 차감, 혜택 우선 사용, 요청 키 중복 방지
- 전체 취소: 원거래의 유료·혜택 잔액 복원, 취소 중복 방지, 추가 원장 기록
- 거래 내역 및 미지급 코인 정산 시뮬레이션 (1%, 부가세 포함 가정)
- SQLite 영속 저장, 반응형 한국어 UI

## 중요한 범위

모든 데이터는 데모입니다. 외부 결제수단은 모의 승인만 기록하며 실제 결제 API를 호출하지 않습니다. 로그인·가맹점 격리·고객 본인인증·실제 충전·QR 승인·서명 통지·정산 배치·송금·단말 등록은 아직 구현하지 않았습니다. 공개 서비스나 실제 자금 운용에 사용하지 마세요.

온라인 간편결제는 지원 PG 계약 및 가맹점·기기별 지원 조건에 맞춰 서버 승인·조회·취소·서명 통지를 구현해야 합니다. 오프라인 카드/Apple Pay/삼성페이는 지원 카드 단말기와 VAN SDK/API가 필요하며, 웹앱만으로 일반 태블릿 NFC 수납을 구현할 수 없습니다. 네이버페이도 온라인/오프라인 계약·지원 방식을 별도 확정해야 합니다. 코인은 자체 공통 원장으로 관리하며 Apple/Samsung Wallet 등록 기능과 별개입니다.

다음 단계는 결제 파트너 선정, 운영 정책 확정, PostgreSQL 기반 다중 사용자 원장, 권한·본인인증·QR 및 파트너 샌드박스 연동입니다. 2,000대 운영과 보안·복구·부하 검수는 완료되지 않았습니다.

## Android 태블릿 네이티브 앱

상세 기획서 v1.5를 기준으로 `android/`에 Kotlin 앱을 추가했습니다. 설치·빌드·서버 연결과 화면별 구현 범위는 [Android 안내](android/README.md)를 참고하세요. 실제 인증·고객 QR·외부 결제 연동 전의 데모입니다. 전체 취소는 서버에서도 사유 2~200자를 요구하며 DB에 기록합니다.
